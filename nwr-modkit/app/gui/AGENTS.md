# GUI APP NOTES

## OVERVIEW

NW.js GUI modifier. The app is now a React + Vite + TypeScript project using the shared `@rpgmv-modkit/ui` component library. The game-facing app loads the Vite production bundle through `dist/index.html`.

## WHERE TO LOOK

| Task | Location | Notes |
| --- | --- | --- |
| Main source | `src/App.tsx`, `src/hooks/useAppState.ts` | React components and business logic. |
| Business modules | `src/*.ts` | ES modules for bridge, catalog, runtime state, etc. |
| Loaded app shell | `dist/index.html` | Vite production output; NW.js `main` points here. |
| Build config | `package.json`, `vite.config.ts`, `tsconfig*.json` | Scripts: `dev`, `build`, `preview`. |
| Catalog data | `../../output/extract/data/` | Generated by extraction scripts when missing/stale. |
| Launcher | `../../tools/launch-gui.ps1` | Build output is loaded from `dist/index.html`. |

## CONVENTIONS

- Build with `npm run build` (`tsc -b && vite build`). Output goes to `dist/`.
- Use only `@rpgmv-modkit/ui` components and Tailwind utility classes; no custom `.css` files.
- Node built-ins are loaded at runtime via `require` so the bundle works under NW.js node integration.
- NW Node globals are expected. Browser-only assumptions can break launch.
- `launch-gui.ps1` may run setup and data extraction before opening the app.
- Treat UI catalog size as large: item, skill, actor, map, troop, variable, and switch lists are paged.
- Keep bridge command payloads compatible with `runtime/bridge`.

## ANTI-PATTERNS

- Do not edit files under `dist/` as the primary source. Change `src/`, then rebuild.
- Do not edit generated NW runtime files in this directory: `*.dll`, `*.exe`, `*.pak`, `*.dat`, `*.bin`, `locales/`, `swiftshader/`.
- Do not rely on `npm test`; this package has no test script.
- Do not assume extracted catalog data exists. Launch scripts can generate it.
