# 工具使用说明

## 首次准备

工具默认假设 `zs2_modkit` 位于游戏根目录下：

```text
再刷一把2：金色传说/
  Game.exe
  www/
  zs2_modkit/
```

如果工具目录放在别处，复制配置示例：

```powershell
Copy-Item .\config.example.json .\config.local.json
```

然后把 `config.local.json` 里的 `gameRoot` 改成游戏根目录。脚本也支持通过 `-GameRoot` 参数或 `ZS2_GAME_ROOT` 环境变量指定。

## GUI 修改器

启动：

```powershell
cd "F:\SteamLibrary\steamapps\common\再刷一把2：金色传说\zs2_modkit"
.\tools\launch-gui.ps1
```

首次启动会按需完成几件事：

- 安装 GUI 所需 npm 依赖。
- 编译 `app/gui/app.ts` 为本地运行用的 `app/gui/app.js`。
- 生成 NW 运行时硬链接。
- 检查并导出 `www/data.pak` 和 `www/useData`，让物品、角色、技能、地图、敌群、称号等列表可显示。

GUI 点击“启动游戏”后，会启动原始 `Game.exe` 并通过 `runtime/bridge` 注入本地 bridge。

界面缩放说明：

- 推荐正常窗口宽度 `1120` 左右；最小窗口支持到 `760x560`。
- Windows 显示缩放为 125%/150%，或窗口高度较低时，GUI 会自动进入页面滚动模式。
- 进入滚动模式后，大分类导航会固定在顶部栏下方，二级分类固定在大分类下方；点击大分类不会直接把页面滚到二级分类位置。
- 物品、技能、宝宝、地图、敌群等长列表默认分页，点击“首页/上一页/下一页/末页”翻页；搜索会回到第一页，直接输入/选择 ID 时才会定位到对应页。

## 修改器范围

常用功能：

- 金币、变量、开关。
- 经验、金币、掉落等倍率。
- 战斗选项。
- 物品添加。
- 角色编辑。
- 技能添加。
- 天赋点修改。
- 称号解锁。
- 换装解锁。
- 地图挂机、敌群挂机。
- 宝宝编辑：添加宝宝技能，修改可学习点数/技能槽位。

倍率说明：

- `expRate`、`goldRate` 影响战斗奖励和脱机/敌群挂机结算。
- `dropRate` 影响真实战斗掉落和脱机/敌群挂机掉落模拟；`0` 表示不掉落，`1` 表示原始概率，大于 `1` 会放大概率并封顶到 100%。

已按当前游戏移除参考项目里的钓鱼功能和熟练系统。

## CLI 修改器

先启动带 bridge 的游戏：

```powershell
.\tools\launch-runtime.ps1
```

查看状态和发送命令：

```powershell
node .\tools\trainer-send.mjs status
node .\tools\trainer-send.mjs ping
node .\tools\trainer-send.mjs gold.add 10000
node .\tools\trainer-send.mjs item.add item 5 10
node .\tools\trainer-send.mjs trainer.options.set expRate=2 goldRate=2 dropRate=3 noSkillCost=true
node .\tools\trainer-send.mjs trainer.hooks.info
node .\tools\trainer-send.mjs baby.slots.set 1 8
node .\tools\trainer-send.mjs baby.skill.learn 1 1890 passive
node .\tools\trainer-send.mjs save 1
```

宝宝被动技能不会自动修改可学习点数；需要扩槽时单独使用 `baby.slots.set` 或 `baby.slots.add`。

状态和事件文件位于：

```text
runtime/bridge-state/state.json
runtime/bridge-state/commands.jsonl
runtime/bridge-state/events.jsonl
runtime/bridge-state/bridge.log
```

这些文件是运行时状态，不需要提交到仓库。

## 离线存档编辑器

启动：

```powershell
.\tools\launch-save-editor.ps1
```

浏览器页面打开后选择 `www/save/config.rpgsave`、`global.rpgsave` 或 `fileN.rpgsave`。编辑 JSON 树后可以导出新的 `.rpgsave` 或 JSON。

当前存档格式：

```text
base64 -> zlib inflate -> MessagePack -> JSON
```

离线存档编辑器只保留通用 JSON 树形编辑、导入导出和校验功能；天赋、称号、换装等快捷功能放在运行时 GUI 修改器里。

## 数据和存档导出

完整导出：

```powershell
.\tools\extract-all.ps1
```

单独导出：

```powershell
node .\tools\extract-data-pak.mjs
node .\tools\extract-usedata.mjs
.\tools\extract-saves.ps1
```

输出位置：

```text
output/extract/data/      RPG Maker 数据 JSON
output/extract/useData/   useData JSON 和 MessagePack
output/extract/save/      存档 JSON 和 MessagePack
```

`output/extract` 是本地生成目录，仓库只保留 `.gitkeep`。

## 重新打包存档

默认把 `output/extract/save/*.json` 重新打包到 `output/repack/save`：

```powershell
.\tools\encrypt-saves.ps1
```

只打包指定槽位：

```powershell
.\tools\encrypt-saves.ps1 -Ids 1,3 -NoConfig
```

脚本会写出 `_repack-report.json`，并对每个输出文件做反解校验。`verified=true` 才算成功。

## 清理生成产物

预览：

```powershell
.\tools\clean-runtime.ps1 -IncludeDependencies -DryRun
```

实际清理：

```powershell
.\tools\clean-runtime.ps1 -IncludeDependencies
```

清理内容包括 NW 运行时硬链接、GUI 编译产物、Vite dist、tsbuildinfo、解包数据、重打包存档、bridge 状态日志和 npm 依赖目录。清理后再次启动工具会自动按需生成。

## 复刻 Skill

`zs2_modkit/skills` 是随项目保存的 Codex skill，用来让另一个 Codex 从零复刻这套项目。它包含：

- `SKILL.md`：触发说明和核心流程。
- `references/rebuild-playbook.md`：从零实现路线。
- `references/formats-and-contracts.md`：数据格式、bridge 命令和验证合约。
- `assets/zs2_modkit_template`：不含运行时生成产物的干净模板。
- `scripts/scaffold-zs2-modkit.ps1`：把模板复制到目标游戏目录的脚本。

在当前游戏根目录下可以这样测试 scaffold：

```powershell
.\zs2_modkit\skills\scripts\scaffold-zs2-modkit.ps1 -GameRoot "." -DryRun
```

要对另一个游戏目录生成项目：

```powershell
& ".\zs2_modkit\skills\scripts\scaffold-zs2-modkit.ps1" `
  -GameRoot "目标游戏目录" `
  -RunSetup
```

如果需要让 Codex 自动发现这个 skill，可以把 `zs2_modkit/skills` 作为 `zs2-modkit-builder` 放到 Codex 的全局 skills 目录；随项目归档时保持当前路径即可。
