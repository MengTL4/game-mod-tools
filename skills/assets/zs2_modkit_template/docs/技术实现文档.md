# 技术实现文档

## 设计范围

`zs2_modkit` 是本地单机工具集，不改写原游戏文件。运行时修改器通过本地 extension 注入游戏页面，离线存档编辑器只处理用户选择的 `.rpgsave` 文件。仓库不提交游戏本体文件、解包数据、存档、日志、运行时状态或 npm 依赖。

## 路径解析

脚本按以下优先级定位游戏根目录：

1. 命令行参数 `-GameRoot`。
2. 环境变量 `ZS2_GAME_ROOT`。
3. `config.local.json` 中的 `gameRoot`。
4. `zs2_modkit` 的父目录。

有效游戏根目录必须包含 `www/index.html`。运行时会设置：

```text
ZS2_MODKIT_ROOT=<zs2_modkit>
ZS2_GAME_ROOT=<游戏根目录>
```

## 运行时 bridge

参考项目的硬链接 NW 启动器可以注入 bridge，但当前游戏会在约 2 秒后关闭窗口。当前适配改为启动原始游戏：

```text
GUI/CLI
  -> Game.exe --load-extension=<zs2_modkit/runtime/bridge>
  -> content.js 注入 page-bridge.js
  -> page-bridge.js 读写 runtime/bridge-state/*.jsonl
```

bridge 会修正存档目录到 `www/save`，轮询 `commands.jsonl`，把执行结果写入 `events.jsonl`，并定期写 `state.json`。已验证 `hasParty`、`hasVariables`、`hasSwitches`、`hasDataManager`、战斗奖励 hook 和掉落倍率 hook 可用。

经验、金币倍率通过 BattleManager 奖励流程和角色/队伍 gain 方法兜底处理。掉落倍率分两条路径：

- 真实战斗：优先 patch `Game_Enemy` 原型；如果当前游戏没有暴露该全局类，则从 `$gameTroop.members()` 的真实敌人实例原型链动态 patch `dropItemRate()` 和 `makeDropItems()`。
- 脱机/敌群挂机：不依赖真实战斗场景，使用导出的敌群/敌人/drop 数据模拟经验、金币和掉落，并按同一个 `dropRate` 放大概率。不要为了计算奖励临时 `new Game_Troop().setup()` 或调用敌人 `die()/refresh()/makeDropItems()`，这些真实战斗插件路径会污染后续手动战斗和存档。

`dropRate=0` 表示禁用掉落，不能被当作默认倍率 `1`；未知或空值才回退到 `1`。

脱机/敌群挂机的掉落模拟可以使用导出的 JSON 数据，但真正调用 `party.gainItem()` 时必须重新映射到运行时 `$dataItems/$dataWeapons/$dataArmors` 的对象引用；映射失败的掉落放入 `skippedDrops`，不能把导出 JSON 对象直接交给背包插件。

脱机/敌群挂机和敌人图鉴解锁只写 `ConfigManager.enemyBook` 的敌人已见标记，不直接构造 `$gameSystem._revealedEnemyWeaknesses`。弱点表是按敌人 ID 存数组的运行时结构，bridge 会在状态刷新和保存前把历史布尔/数字/字符串坏值修成数组，避免 `Game_System.addEnemyWeaknessElement()` 在后续真实战斗里把非数组当数组调用。

指定战斗通过 `battle.start` 命令实现。命令可以直接传 `troopId`，也可以留空并默认读取变量 `399`；bridge 会优先走当前地图解释器的 `command301`，这样不依赖全局 `Scene_Battle` 暴露，失败时再尝试 `BattleManager.setup()` 的直接启动路径。穿墙通过 `map.through.set` 和 `map.through.toggle` 调用 `$gamePlayer.setThrough()`，并把当前 `through` 状态写回 `state.json` 的 `map` 摘要。

## GUI 数据来源

GUI 列表依赖 `output/extract/data` 和 `output/extract/useData` 中的可读 JSON。`launch-gui.ps1` 会检查关键文件：

```text
_index.json
System.json
Items.json
Weapons.json
Armors.json
Actors.json
Skills.json
MapInfos.json
Troops.json
Enemies.json
CommonEvents.json
```

如果 `data.pak` 导出文件缺失、过期，或仍是旧 AES envelope，脚本会重新导出 `www/data.pak`。如果 `useData` 导出缺失或比游戏源文件旧，脚本会重新导出 `www/useData`，用于称号等列表。

## GUI 自适应和导航

GUI 是 NW 页面，布局以密集工具面板为主。窗口默认 `1120x760`，最小 `760x560`。`app/gui/app.ts` 会根据 `window.innerWidth`、`window.innerHeight`、`visualViewport.scale` 和 `devicePixelRatio` 切换：

- `page-scroll-mode`：窄窗口、低高度窗口或高缩放下启用页面滚动，避免内部网格和列表互相挤压。
- `zoom-scroll-mode`：显示缩放达到约 125% 以上时收紧间距，并提高虚拟列表行高。

顶部栏、大分类 `.tool-nav` 和二级分类 `.tool-section-nav` 都不能使用固定写死的偏移。`syncStickyNavMetrics()` 会测量实际高度并写入 CSS 变量：

```text
--topbar-sticky-offset
--tool-nav-sticky-height
--section-nav-sticky-height
```

分类跳转使用 `scrollActiveToolAreaToTop()`，它会识别真正的滚动容器，兼容 `body` 滚动和 `document.scrollingElement` 滚动。点击大分类时定位到大分类导航，点击二级分类时定位到二级导航，同时保留大分类可见。不要把滚动目标直接改回 `workspace.scrollIntoView()`，否则缩放模式下会跳过大分类入口。

虚拟列表行高由 `catalogRowHeight()` 统一决定，渲染时写入 `--catalog-row-height`，CSS 用这个变量约束 `.catalog-row` 高度。调整列表行内容、按钮或 chip 样式时，需要同步考虑 760 宽、125%/150% 缩放下是否会重叠或横向溢出。

## data.pak

`manifest.enc` 使用 AES-256-CBC：

```text
key = UTF-8 bytes of "e5c8bec60f27777fdc7161d01125819d"
iv = envelope.iv hex
ciphertext = envelope.encryptedData hex
```

`www/data.pak`：

```text
4 bytes  magic "PAKX"
4 bytes  binary index length, little-endian
N bytes  binary index
...      sequential PAK1 entries
```

当前导出脚本不依赖二进制索引，直接顺序解析 `PAK1`：

```text
4 bytes   magic "PAK1"
8 bytes   type, null padded
4 bytes   original size, little-endian
4 bytes   compressed size, little-endian
4 bytes   filename length, little-endian
20 bytes  reserved metadata
N bytes   filename
M bytes   zlib payload
```

每个 `PAK1` 的 zlib payload 仍是旧 AES JSON envelope：

```json
{
  "iv": "...",
  "encryptedData": "..."
}
```

用 `manifest.key` 的前 32 个 UTF-8 字节执行 AES-256-CBC 解密后，才是 GUI 读取的 RPG Maker JSON 数组/对象。

## useData

`www/useData` 下文件没有 `.data` 后缀。格式：

```text
gzip inflate -> skip first 20 bytes -> MessagePack decode
```

脚本输出 `.json`、`.msgpack` 和 `_index.json`。

## 存档

当前 `.rpgsave` 没有参考项目的 v2 AES/HMAC 外壳。格式：

```text
base64 text -> zlib inflate -> MessagePack -> JSON
```

重新打包：

```text
JSON -> MessagePack encode -> zlib deflate -> base64 text
```

`encrypt-saves.mjs` 会对输出做反解并比较 JSON，报告中 `verified=true` 表示可逆校验通过。

## 运行时功能分布

- `常用`：金币、变量、开关、倍率和战斗选项。
- `物品角色`：物品添加、角色编辑、技能添加、天赋点。
- `宝宝`：宝宝列表、宝宝技能添加、可学习点数/技能槽位。
- `成长解锁`：称号、换装。
- `脱机挂机`：地图挂机。
- `敌群挂机`：敌群选择和挂机。

钓鱼功能和熟练系统已移除。离线存档编辑器不保留快捷修改入口，只提供通用 JSON 树形编辑。

倍率面板里的 `dropRate` 同时影响真实战斗和脱机/敌群挂机。倍率为 `10` 时，常规掉落概率和敌人 note 中的 `<Enemy Drops>` 百分比会按 10 倍计算并封顶到 100%；倍率为 `0` 时不会产生掉落。

战斗面板的“指定战斗”会发送 `battle.start`；填写敌群 ID 时直接使用该 ID，留空时读取变量 `399`。地图面板的“穿墙”会发送 `map.through.set`，GUI 根据 bridge 状态里的 `map.through` 显示当前开关状态。

宝宝被动技能会同时写入 `_skills`、`_realSkills` 和 `_zs2ModkitBabyPassives`。最后一个字段是修改器的持久化缓存，用来在游戏刷新宝宝技能时把被动重新并回运行时技能数组；可学习点数/技能槽位只由 `baby.slots.*` 命令修改，添加或删除被动不会自动改槽位。

## 复刻 Skill

`zs2_modkit/skills` 是本项目自带的 Codex skill，用来把“如何从零实现这套工具”的思路、流程和模板一起归档。它不是运行时修改器的必要依赖，删除它不会影响 GUI、bridge、解包或存档脚本运行。

组成：

```text
zs2_modkit/skills/SKILL.md
zs2_modkit/skills/agents/openai.yaml
zs2_modkit/skills/references/rebuild-playbook.md
zs2_modkit/skills/references/formats-and-contracts.md
zs2_modkit/skills/assets/zs2_modkit_template/
zs2_modkit/skills/scripts/scaffold-zs2-modkit.ps1
```

其中 `assets/zs2_modkit_template` 是干净模板，只保留源码、脚本、文档、配置示例和 package 文件，不包含：

```text
Game.exe / nw.dll / node.dll 等 NW 运行时
node_modules
output 里的导出或重打包 payload
runtime/bridge-state 状态文件
app/save-editor/dist
app/gui/app.js
*.tsbuildinfo
*.jsc 字节码
```

`scaffold-zs2-modkit.ps1` 会从 skill 所在目录反推模板路径，因此 skill 随项目保存在 `zs2_modkit/skills` 时也能运行：

```powershell
.\zs2_modkit\skills\scripts\scaffold-zs2-modkit.ps1 -GameRoot "." -DryRun
```

如果要安装到 Codex 全局 skills 目录用于自动发现，目录名应使用 skill 名称 `zs2-modkit-builder`；当前 `zs2_modkit/skills` 位置主要用于随项目一起分发和归档。
